# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：云端当前版本列表固定限高后，相似榜排在末尾，触屏上容易忽略列表内部还有内容；解决方案选择：当前版本随页面完整展开，仅勾选历史版本时保留 640px 内部滚动，并显示当前数量、筛选数量及相似榜是否存在；解释：当前分组数量少，优先保证可发现性；历史版本可能持续增长，限高避免长历史占据整个管理页，相似榜状态不受文本筛选影响。

- 问题：宽表既要表内横向滚动，又要表头随页面纵向悬浮，单个 overflow 容器会改变 sticky 的滚动参照；解决方案选择：悬浮表头放在横向滚动容器外并同步 scrollLeft；解释：额外维护滚动同步，换取表头继续随外层页面纵向悬浮。

- 问题：冻结股票识别区占用过宽会压缩平板宽表的可见数据；解决方案选择：总榜、场景榜和相似榜统一使用 50px 排名列与 120px 股票列，名称在上、代码在下；解释：在较小横向占用与滚动时仍能识别股票之间取平衡。

- 问题：表格的双轴滚动越界限制在没有内部纵向空间时会吞掉触屏拖动，但真实限高表格滑到边缘又不应带动整页；解决方案选择：随页面展开的普通表格只限制横轴越界，纵轴 auto；显式限高的内部双轴滚动区使用 overscroll-behavior: contain；解释：按是否拥有纵向滚动空间选择滚动链行为，同时保留表内横向控制和平板页面自然纵向拖动。

- 问题：批次间不断增长的耗时会让按轮询重算的预计剩余时间反而上升；解决方案选择：仅在任务、阶段或完成量/总量变化时重新采样，等待期间保留估计并倒计时至零；解释：进度反馈稀疏时以稳定读数为优先，下一批真实反馈到达后再校正，不把界面轮询当作新进度证据。

- 问题：首屏预载所有业务页面及研究数据会增加启动资源和结果库扫描成本；解决方案选择：桌面业务路由延迟加载，onlyExplicitManualChunks 防止页面块吞并共享依赖，相关性规则统计由用户点击后读取；解释：以首次进入页面或点击时的等待换取更小首屏资源，并让用户区分加载规则统计与运行研究的成本。

- 问题：异动记录随监控时间增长，全部渲染会挤占平板交互资源；解决方案选择：内存保留最近 600 条同股同类记录，筛选后右栏最多展示 200 条，重复触发更新时间并计次；解释：沿用原右栏展示规模，以更大的历史池支持类型与涨速周期切换，平衡保留范围和渲染成本。

- 问题：777 CSS px 竖屏保留导航时，并列右栏会把行情表压得过窄；解决方案选择：监控页在 900 CSS px 以下上下排列行情与流水，横屏继续并列；解释：为导航、间距和行情列留出空间，避免缩小字体；调整时用 777×1164 与 1164×777 视口分别检查竖屏和横屏。

- 问题：自动暂停原因常驻会持续占用监控页面空间；解决方案选择：原因显示 5 秒后清除，暂停状态继续由开关展示；解释：在阅读瞬时反馈的时间与页面空间之间取平衡。

- 问题：市场统计需要独立列，又不能增加实时监控顶部高度，竖屏保留导航后横向空间有限；解决方案选择：工具栏并列控制区、独立横向滚动的指数区与紧凑统计列，统计列通常宽 170px，900 CSS px 以下缩为 140px，同时缩小控制按钮横向留白，涨跌以红绿比例条比较（不含平盘），成交额仅保留两市合计并按亿元取整；解释：以减少按钮留白和同时可见指数数量换取统计常驻右侧，保留原工具栏高度和按钮字体；平盘、有效家数和日期放入提示信息。

- 问题：下载与批次事务交替上报、重试和局部补救会反复改变计数口径，按事件顺序分配进度会跳跃；解决方案选择：同一工作段的下载、重试、写入事件共享计数，股票按成功提交数推进，整段事务仅在提交后报完成；总条按工作段等分，未知总量保留已确认位置，只有任务完成事件显示 100%；解释：百分比表示流程完成度而非耗时比例，等待网络或事务时保持位置并显示状态，避免用虚构进度换取表面连续性。

- 问题：量比分时补齐需要持续取得行情日期、交易状态与进度，但用户希望暂停监控表格时也能单独拉取；解决方案选择：量比默认关闭，由独立手动开关控制后台补齐，两个开关共用现有行情快照轮询，任一开启便轮询，单独拉取时只更新进度，刷新失败或离开页面停止拉取；非交易时段仅自动暂停监控，手动量比拉取按行情日期继续补齐；解释：复用行情缓存与交易有效性检查，避免两套轮询竞争同一补齐缓存；代价是单独拉取仍会调用完整快照接口，监控暂停表示表格和异动记录冻结，不表示所有行情请求停止。

- 问题：全市场同轮可能有多只量比突破，逐股通知会堆积并打断操作；解决方案选择：通知复用现有日内量比新高事件，每轮合并一条，正文最多列出 5 只，其余提示查看异动记录，使用固定通知 ID 更新 Android 通知；解释：保留全部页面异动记录，以通知展示范围换取系统通知栏可读性；开关持久化且默认关闭，启用时申请系统权限，通知失败不暂停行情刷新。

- 问题：异动刷新会在顶部插入记录并重新排序，浏览历史时触屏位置容易跳动；解决方案选择：流水离开顶部后保留当前展示快照，后台继续记录，回到顶部或点击“回到最新”再更新；解释：以历史浏览期间暂缓展示新记录换取稳定阅读，不暂停行情请求或系统通知。

- 问题：量比后台补齐把 60 秒未轮询视为页面离开，刷新间隔过长会使排队任务失效；解决方案选择：实时监控刷新间隔可设 1–30 秒，默认沿用 1 秒；解释：用最长 30 秒为网络请求耗时和调度延迟留出余量，同时允许降低刷新频率，不改变后台离页停止的 60 秒判定。
