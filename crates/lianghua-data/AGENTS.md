# 组件取舍

后续 agents 修改本组件时请继续维护本文件。

- 本 crate 负责持久化、数据库结构、领域配置和数据到表达式运行时的转换。
- 评分结果库的建表、批量写入、数据库排名与补排名统一位于 `data::scoring_store`。
- 可以依赖 `lianghua-model` 的共享类型，禁止依赖 scoring、download、backtest 或应用层 crate，确保依赖无环。
- 不在 data 中实现评分规则计算或把评分序列构造成结果行。
- 只运行 `cargo test -p lianghua-data`，不要因此触发全 workspace 测试。
- 陈氏筹码从输出日前的预热首根 K 线价格区间初始化，再按日换手因果演化并动态扩展分桶；禁止使用整个预热窗口的未来最高/最低价铺设初始成本，否则早期筹码状态会带入后视价格范围。
- 改变筹码初始化或逐日迁移语义时必须提升 `CYQ_CHEN_SCHEMA_VERSION`，强制旧库完整重建，禁止在旧状态上混用新算法续算。
- 后验规则的 `confirm_after` 按该股票有效 K 线根数计时；确认只在当前日对原买入批次尚存筹码改归属，不回写交换日快照，不重演已经成交的卖出。批次按分桶、持有人实际卖出比例衰减，同龄规则首个命中生效，避免重复归因。
- 后验表达式限定有限窗口因果函数，禁用 `LAST`（它读取整段输入尾部）以及未保存递归状态的无限回溯函数；停牌补历史按表达式需求与初始化预热的较大值读取，不能只补初始化预热长度。
- 新筹码 schema 4 将原始精度分桶和有限待确认批次放入每股唯一的 `cyq_chen_checkpoint`，与历史快照同事务提交；展示值仍四舍五入。策略指纹包含 schema 版本，避免旧算法或缺失后验状态被静默续算。检查点只保存最新状态，历史修订应走单股重建。

- 场景排名随评分批次写入临时表，再按原排序键在数据库计算全市场排名，避免 Rust 常驻全量场景明细；保留原事务回滚与影子表替换语义。
- 新筹码重建与增量统一每批 8 股、队列缓存 2 批，平衡历史分桶内存峰值与批量读写吞吐；逐日演化不变，避免重建时每个线程积累 128 股快照。

- 新筹码写线程失败会连带关闭发送通道，汇总结果必须优先返回写线程的具体原因，避免 `sending on a closed channel` 掩盖数据库错误；显式计算中断仍通过 Abort 回滚。小批次计算复用 Rayon 任务内的行情连接，检查点写入复用预编译语句，不通过扩大在途快照量提速。

- 全量新筹码重建只向空临时库写入，每个 8 股批次独立提交，最后才写元数据、建索引并替换正式库；全量大事务的 flush 不释放事务生命周期内的积累，因此失败时丢弃临时库，不再要求临时库整体回滚。增量写正式库仍保留原子事务。
- 全量重建计算最多 4 个 Rayon 工作线程，临时写库限制 512MB 缓冲和 2 个数据库线程，给行情、历史分桶及界面留出空间，避免两层并行与数据库默认内存预算一起挤占进程；这是吞吐与移动端内存峰值的折中，不是进程总内存硬上限。

- 正式新筹码库初始化和全量重建前清理严格匹配 `.cyq_chen.db.rebuild-<pid>-<timestamp>.tmp` 的残留及其 WAL/溢出目录；清理与整个重建过程共用目录文件锁，拿不到锁时初始化跳过清理、第二个重建直接报忙。锁文件保留，不能删除后重新创建造成跨进程锁失效；崩溃由系统释放锁，下一次访问再清理。使用 Rust 1.89 稳定的文件锁 API，跨平台保护活动重建，不依赖 PID 或残留文件年龄猜测任务存活。
