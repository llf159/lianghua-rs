# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：相似榜内存查询连接默认按整机资源分配，抽样中间结果会挤占应用和编辑器内存，默认溢写目录又跟随工作目录落到系统盘；解决方案选择：查询连接使用 512MB 缓冲管理预算、2 个数据库线程，溢写固定放在数据源目录的 `.strategy_similarity.tmp/`；解释：以部分查询吞吐换取平板和桌面的内存余量，超预算中间数据与行情共盘；预算不包含 Rust 指纹及 DuckDB 所有分配，不能视为进程内存硬上限。

- 问题：历史待重算记录会把日常计算的默认起点拉回全历史；解决方案选择：默认起点只按结果库末日后的首个行情交易日确定，结果为空时取行情起点，历史欠账独立展示并继续保留；解释：日常增量与历史修复分别由用户选择，默认日期不代表旧结果已有效，局部计算仍只清除实际完成区间的欠账。

- 问题：总体量能接入走势估计后，重拟合模型或比较不同模型会混入结构系数变化；解决方案选择：内嵌版本固定的 `market_activity_model.json`，量能调整只比较同一模型中实际量比与全部量比为 1 的输出，价格防线仍由结构引擎判断；解释：将量能输入带来的读数变化与重训练差异分开；更新模型时须核对运行特征、参数版本及兼容性。

- 问题：安卓长尾股票难以靠页面反馈还原耗时；解决方案选择：记录阶段切换、精排规模以及耗时至少 5 秒的股票，写日志前释放进度锁；解释：保留慢任务证据，同时避免逐股日志噪声及日志 I/O 阻塞进度查询。

- 问题：全策略回测把完整明细累积到返回数组后，Rust 结果、Tauri 序列化和前端 JSON 会在交付阶段叠加内存峰值；解决方案选择：每个策略线程算完摘要、样本、分层和相似度后立即将明细流式写入系统临时目录，主响应只返回摘要，点击时读取已算缓存且不重新计算；解释：继续由 `parallel_batch_size` 约束计算缓存，同时避免全量明细在应用层和跨端传输中常驻多份，新回测开始时清理上一轮缓存，失败的未提交缓存由写入器自动清理。

- 问题：逐策略构建相似度会为每条策略重扫一次区间内全部 `rule_details`，逐策略贡献度也会重复执行连接查询；解决方案选择：相似度只扫描一次并保存按 `(股票, 日期)` 的 64 位哈希排序紧凑行，查询时二分统计重叠；无限定股票池时贡献度改为一次 SQL 分组聚合，有限定股票池时保留逐策略过滤口径；解释：将主要数据库开销从随策略数增长的全表扫描降为单次扫描，同时避免恢复字符串键与逐键 `Vec` 的高内存缓存；64 位哈希存在理论碰撞但概率可忽略，换取显著更低的常驻内存。

- 问题：后验查询按锚点展开直到参考日的全部行情，同股多锚点会重复生成大量中间行，而每股单锚点使用新查询反而有额外开销；解决方案选择：同股多锚点时共用股票行情序号，通过 ASOF 定位后截取后续 N 行，每股单锚点保留原查询；解释：减少重复展开，不改变批次与并发，并保留停牌、锚点当天缺行情及先截取后过滤无效价格的语义。

- 问题：表达式回测若自动给分、挑选最佳参数或预排序鲁棒性表，会让研究读数被当成生产推荐；解决方案选择：表达式内部按 ±1 计分，方向取页面选择，正式 points/dist_points 不参与统计；不产出建议分值或最佳参数，参数表默认按枚举顺序展示、仅由用户主动排序；解释：保留人工定分与比较相邻参数的职责，正式评分和排名仍需另行验证，页面须说明表达式统计与正式分值大小无关。

- 问题：expanding walk-forward 的 fold 数量、首个训练窗口长度与增量回归最小训练样本必须固定，否则短区间会切出无法统计的样本外窗口；解决方案选择：fold 上限 8、首个训练窗口取 `max(长度/4, 20)` 个交易日、增量回归要求训练行至少 `max(30, 核心策略数 × 5)` 且样本外至少 20 个共同有效日，不足的 fold 标记 `status=insufficient`、只返回时间区间与样本数；解释：IC t 值与 ridge 回归都需要足够长的训练/测试序列，宁可少给一个 fold 的结论，也不要用几个交易日的噪声充当样本外证据。

- 问题：剔除样本不足的 fold 会让仅一个有效窗口的参数显示为 1/1，弱化覆盖不足的风险；解决方案选择：正窗口分母取全部 fold，不足窗口计入分母但不计为正，并注明不足数量；解释：按非正处理不足样本，使不同参数的证据覆盖可比，以保守读数避免小分母造成的误导。

- 问题：核心策略彼此高度相关时，增量回归的正规方程会退化，普通最小二乘要么无解要么给出巨大且不稳定的系数；解决方案选择：先把 predictor 与 target 标准化，解 `(R + λI)β_z = r_xy`（λ = 0.1，复用 `dimension::{calc_linear_orthogonal_diagnostics}` 与相关性与正交研究同一口径），再换算回原始尺度，样本外增量按 `incremental = y_test - Σβ_i x_i_test` 计算（不减 train intercept），并把 predictor 数量限制为最多 8 个；解释：标准化后岭系数作用在单位方差上，共线方向上系数被平均分配而不是爆炸；test 不减 train intercept 时增量均值就是控制核心策略后的样本外增量 alpha，而减掉 intercept 会把训练期与样本外的水平差当成预测值吸收掉，让 “candidate = core + 常数 alpha” 这种稳定 alpha 显示成 0。

- 问题：数据库抽样核验若缩小历史候选池或套用最新参数，重算值就无法与保存的相似度结果直接比较；解决方案选择：沿用被抽日期保存的参数和完整候选池，仅限制目标股票，在签名校验后直接返回内存结果，跳过持久化、待重算记录清除与任务进度更新；解释：目标规模较小但历史准备成本仍保留，以计算口径一致性优先；旧算法版本不强行比较，标为抽样未完成。

- 问题：评分和走势相似度结果共库时，独立计算或查询会反复打开同一结果文件，写入相似度还会改变评分库；解决方案选择：相似度四张结果及配置表独立存入 strategy_similarity.db，计算/页面在内存数据库只读挂载评分、行情和相似度库，以临时视图维持查询口径；解释：相似度写入不触碰评分文件，读完关闭挂载连接才开相似度写实例；按用户要求不迁移、不回退读取评分库内旧相似度表。

- 问题：相似榜按日保存，但清除原始库维护记录也会改变行情文件签名，导致刚算的结果立即过期；解决方案选择：提交相似榜后只清当日欠账，再仅同步行情水位与本次输入相同的快照，保留各自评分、触发和资料签名及其他日期欠账；解释：维护记账变化不等于计算输入变化，避免再次扫描历史评分，同时中断最多留下需要重新计算的快照，不会把行情变更前的旧快照认证为有效，也不会因单纯清账让同一行情版本下已完成的其他日期过期。

- 问题：历史评分欠账会硬阻断已完成当日排名的每日走势相似任务；解决方案选择：走势相似计算不再以历史排名待重算记录作为入口门禁，历史欠账继续在排名页展示并由手动重算消化；解释：每日流程可以只计算最新一天，代价是相似度历史样本可能继续使用尚未按修订后行情重算的旧规则触发结果。

- 问题：云端相似榜只同步单日完整结果，而本机总榜快照只含最近五日，无法按默认 90 日样本间隔重新计算数据签名；解决方案选择：展示已有相似榜元数据时，本机历史足够则继续核验签名，本机历史不足则信任已同步的完整结果快照并明确标为未复核水位；解释：相似榜结果、元数据、参数和匹配证据已随快照完整传输，缺少的是重算输入，不能因此拒绝展示；代价是精简历史设备上的后续输入修订无法自动判定该快照过期，需由新云端快照覆盖或在完整历史设备重算。

- 问题：后续跟踪进入普通策略编辑器后，另一次保存会造成规则成功、跟踪失败的半提交，而旧调用方未传跟踪字段不应清掉既有设置；解决方案选择：管理接口按规则稳定 ID 投影跟踪配置，规则与跟踪一次写入 score_rule.toml，tracking 缺省表示保留、空数组表示移除，删除规则时级联删除所属跟踪；解释：保留现有独立 track 存储和执行器兼容性，同时让新建、编辑、取消及删除遵循普通策略的操作边界。

- 问题：最新行情日可能只有部分股票更新，直接用当天已有报价数作分母会把半更新日误判为完整；解决方案选择：应有样本按参考日上市满 60 个交易日且未退市的股票计算，有效率至少 90% 且样本不少于 20 只才生成摘要，否则向前最多 20 个交易日回退；解释：正常停牌只让覆盖率略低于 100%，90% 能容纳停牌与个别缺口，又能拒绝只更新一半的行情；回退后摘要与证据统一使用同一分析日。

- 问题：市场环境需要 20 日个股基线、20 日共同波动、5 日平滑和 5 日变化，按行数直接截取会让不同停牌缺口共用错误的历史长度；解决方案选择：按交易日历读取参考日及之前 80 个市场交易日，所有先行窗口要求连续交易日行，5 日变化只比较同一市场日索引；解释：80 日足以覆盖最长 20 日基线加 5 日平滑与 5 日变化，同时避免为每次分析重算全历史；停牌缺口让对应个股当日特征留空，不用自然日或跳行补齐。

- 问题：原始研究脚本把上市日期缺失视为很早上市，且下跌尾部把缺失收益当作 false 仍放进分母；解决方案选择：正式实现排除上市资格未知的股票并单列数量，尾部比例只用有效涨跌幅样本；解释：避免未知资格混入 60 日样本、避免缺失值稀释尾部读数；旧研究报告的具体数值不能作为这两项的正确性基准，涉及旧效果结论时须按修正口径复核。

- 问题：市场分析页已改为原始行情环境分析，但 `structure_cycle.rs` 与 `market_activity.rs` 仍保留；解决方案选择：只移除页面、前端 API 与 Tauri 命令，保留 `StructureEngine`、`get_market_structure` 及量能模块；解释：本地研究入口 `src/bin/structure_cycle_research.rs` 仍引用这些符号，删除会让该研究工具无法编译；正式市场环境分析不读取这两个模块，二者不再属于页面运行时依赖。

- 问题：逐项罗列市场读数难以形成整体判断，而将不同群体的事件比例直接合成分数会混淆观察与预测；解决方案选择：首层以10日方向±0.2解释刻度、5日涨跌和10日个股上涨比例描述处境，再按近5日上攻站稳／下探收回／成果保留／跌破修复解释近期过程；解释：次日结果固定前日参考位且只在结果日计入，保留同群体观察含义，不引入长期旧锚点库存、条件模型或预测总分。每类至少50次事件才解释，作为抑制小样本跳动的展示门槛，同时返回事件人次和不同股票数，不声称统计置信度。

- 问题：仅保留后验成功/失败模板会丢失普通结果，混合路径质量也不能对应固定持有收益；解决方案选择：v15沿用按评分资格及观察窗口触发独立于后验抽取最多50,000个历史窗口，不做结果类别配额，主排序使用次日开盘至评价末日收盘的收缩超额收益，MFE/MAE仅展示；解释：保留规则/路径的条件信息，同时让排序目标对应现有持有期；哈希抽样控制计算规模，不代表收益无偏或已验证增量。上涨/下跌案例只标记超额正负，不参与候选身份或近邻配额。

- 问题：市场窗口内标准化会消掉状态水平，tanh加余弦又会把高换手等正值状态压成几乎相同；解决方案选择：v15将形状与状态分开存储，形状沿用余弦，状态按均值与标准差的欧氏距离d计算100/(1+d)；绝对涨跌和换手率先对每日值做log1p，其余百分数用1个百分点、上涨比例以50%为中心且尺度25个百分点、≥5%上涨比例尺度10个百分点，成交额保留窗口之前最多252日对数基线；解释：使用跨窗口一致的单位，距离为1时状态相似度为50，避免向量归一化或有界激活抹掉幅度；这些单位与252日基线用于可解释比较，不是拟合出的最优参数。形状与状态按有效通道等权平均，缺失跳过；指标仍按趋势、摆动、波动、量能、资金、筹码及自定义七组先组内后组间平均，重复列仍可能改变组内权重，历史板块仅按代码分类。

- 问题：最近邻经过择优，其平均相似度与普通背景90分位的差值受候选规模影响，不能作为可靠性门槛；解决方案选择：v15仅保留N_eff≥8的样本门槛，至多128个同规则背景的匹配提升只作诊断，和样本支持、超额分歧分别展示；解释：128约束每股额外精算成本，匹配提升不认证绝对接近、显著性或收益有效；未校准前不据此拒绝样本或排名。诊断与案例继续共用top_matches_json结构化对象，保持云端列协议；v15统一使旧榜与指纹缓存失效。

- 问题：每日重建历史指纹限制研究覆盖，而文件水位会随正常追加改变；解决方案选择：独立strategy_similarity_cache.db只保留当前候选池的指纹与成熟后验，按旧缓存日期前的逐股行情全列及触发内容校验，正常追加复用，个股历史修订只清该股；基准、评分日历或定义和参数变化整体失效；市场匹配与IDF每次重新计算，规则按名称重映射并稳定排序，JSON启用float_roundtrip；指纹不使用当前名称或行业，股票列表更新不使其失效；解释：内容扫描换取避免重建大量历史窗口，不能把缓存理解为免扫描或保证加速；按批键删除并用Appender追加，避免逐行替换大JSON；批次提交以约束未提交内存，任务完成后才认证ready，中断缓存下次清除。缓存不上云，原只读抽样核验路径仍完全重算且不写缓存。

- 问题：相似榜逐行 INSERT 重复执行 SQL，指纹大 JSON 虽已批量追加但仍按批提交触发 checkpoint；解决方案选择：榜单在原事务内用 Appender 追加并在生成汇总前 flush，指纹专用连接在生命周期内复用 256MB checkpoint 阈值，认证 ready 后显式落盘并恢复；解释：榜单、汇总及生效配置仍一起提交；缓存连接不外借，失败直接关闭该实例，未认证缓存继续按原规则失效，成功收尾包含推迟的 I/O。

- 问题：完整证据回归的200日/两类20日门槛使稀少向上反转长期无输出，任一进退事件缺失又会丢掉价格完整的日期；解决方案选择：完整证据模型继续保留原支持条件，条件不足退到三维价格logistic（至少60日、标准化斜率L2=4、截距各半个成功/失败惩罚），再不足使用同方向真实历史的(s+0.5)/(n+1)；解释：把原门槛改成复杂分支的适用条件，用低维和收缩换取小样本稳定性及覆盖，60日提供约一季度同方向历史且并非可靠性认证；保持既有可用分支的输出，退路单独标明方法，不将缺失填成中性特征或把平滑伪样本计入实际训练日数。

- 问题：季度模型资产在季度末硬失效会让正常新增行情突然失去估计，但直接使用最新资产会泄漏未来训练信息；解决方案选择：选生效日不晚于实际分析日的最近资产，季度末作为建议复核日，超过后仍给原模型估计并提示更新；解释：以可见的模型陈旧提醒代替机械断供，同时保持历史因果边界，刷新页面不会自动重训或增加历史样本。


- 问题：固定种子的策略验证和历史样本抽样依赖随机数生成器及区间采样实现，而 Tauri 通知插件依赖 rand 0.9；解决方案选择：项目统一使用 rand 0.9.5；解释：消除 rand 0.9 与 0.10 并存，同时延续原有抽样版本；将来升级须核对固定种子的输出，StdRng 不保证跨版本一致。
