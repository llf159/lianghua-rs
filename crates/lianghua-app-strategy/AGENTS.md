# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：历史待重算记录会把日常计算的默认起点拉回全历史；解决方案选择：默认起点只按结果库末日后的首个行情交易日确定，结果为空时取行情起点，历史欠账独立展示并继续保留；解释：日常增量与历史修复分别由用户选择，默认日期不代表旧结果已有效，局部计算仍只清除实际完成区间的欠账。

- 问题：总体量能接入走势估计后，若重拟合全部历史或用另一套模型的差值表示量能作用，会混入验证期信息或结构系数变化；解决方案选择：内嵌 `market_activity_model.json`，沿用2011—2020拟合、2017—2020选惩罚的5/10日模型，总体量能调整只比较同一模型中实际量比与全部量比为1的输出，价格防线仍由结构引擎判断；解释：保留研究与运行结果可复核性，把量能带来的读数变化与重训练差异分开；更新模型需从 `research/market_total_activity/models.json` 的 `market5/structure_activity`、`market10/structure_activity` 导出参数，重新核对运行特征和研究脚本，不能仅凭近期行情调整权重。

- 问题：安卓长尾股票难以靠页面反馈还原耗时；解决方案选择：记录阶段切换、精排规模以及耗时至少 5 秒的股票，写日志前释放进度锁；解释：保留慢任务证据，同时避免逐股日志噪声及日志 I/O 阻塞进度查询。

- 问题：全策略回测把完整明细累积到返回数组后，Rust 结果、Tauri 序列化和前端 JSON 会在交付阶段叠加内存峰值；解决方案选择：每个策略线程算完摘要、样本、分层和相似度后立即将明细流式写入系统临时目录，主响应只返回摘要，点击时读取已算缓存且不重新计算；解释：继续由 `parallel_batch_size` 约束计算缓存，同时避免全量明细在应用层和跨端传输中常驻多份，新回测开始时清理上一轮缓存，失败的未提交缓存由写入器自动清理。

- 问题：逐策略构建相似度会为每条策略重扫一次区间内全部 `rule_details`，逐策略贡献度也会重复执行连接查询；解决方案选择：相似度只扫描一次并保存按 `(股票, 日期)` 的 64 位哈希排序紧凑行，查询时二分统计重叠；无限定股票池时贡献度改为一次 SQL 分组聚合，有限定股票池时保留逐策略过滤口径；解释：将主要数据库开销从随策略数增长的全表扫描降为单次扫描，同时避免恢复字符串键与逐键 `Vec` 的高内存缓存；64 位哈希存在理论碰撞但概率可忽略，换取显著更低的常驻内存。

- 问题：后验查询按锚点展开直到参考日的全部行情，同股多锚点会重复生成大量中间行，而每股单锚点使用新查询反而有额外开销；解决方案选择：同股多锚点时共用股票行情序号，通过 ASOF 定位后截取后续 N 行，每股单锚点保留原查询；解释：减少重复展开，不改变批次与并发，并保留停牌、锚点当天缺行情及先截取后过滤无效价格的语义。

- 问题：表达式回测若自动给分、挑选最佳参数或预排序鲁棒性表，会让研究读数被当成生产推荐；解决方案选择：表达式内部按 ±1 计分，方向取页面选择，正式 points/dist_points 不参与统计；不产出建议分值或最佳参数，参数表默认按枚举顺序展示、仅由用户主动排序；解释：保留人工定分与比较相邻参数的职责，正式评分和排名仍需另行验证，页面须说明表达式统计与正式分值大小无关。

- 问题：expanding walk-forward 的 fold 数量、首个训练窗口长度与增量回归最小训练样本必须固定，否则短区间会切出无法统计的样本外窗口；解决方案选择：fold 上限 8、首个训练窗口取 `max(长度/4, 20)` 个交易日、增量回归要求训练行至少 `max(30, 核心策略数 × 5)` 且样本外至少 20 个共同有效日，不足的 fold 标记 `status=insufficient`、只返回时间区间与样本数；解释：IC t 值与 ridge 回归都需要足够长的训练/测试序列，宁可少给一个 fold 的结论，也不要用几个交易日的噪声充当样本外证据。

- 问题：剔除样本不足的 fold 会让仅一个有效窗口的参数显示为 1/1，弱化覆盖不足的风险；解决方案选择：正窗口分母取全部 fold，不足窗口计入分母但不计为正，并注明不足数量；解释：按非正处理不足样本，使不同参数的证据覆盖可比，以保守读数避免小分母造成的误导。

- 问题：核心策略彼此高度相关时，增量回归的正规方程会退化，普通最小二乘要么无解要么给出巨大且不稳定的系数；解决方案选择：先把 predictor 与 target 标准化，解 `(R + λI)β_z = r_xy`（λ = 0.1，复用 `dimension::{calc_linear_orthogonal_diagnostics}` 与相关性与正交研究同一口径），再换算回原始尺度，样本外增量按 `incremental = y_test - Σβ_i x_i_test` 计算（不减 train intercept），并把 predictor 数量限制为最多 8 个；解释：标准化后岭系数作用在单位方差上，共线方向上系数被平均分配而不是爆炸；test 不减 train intercept 时增量均值就是控制核心策略后的样本外增量 alpha，而减掉 intercept 会把训练期与样本外的水平差当成预测值吸收掉，让 “candidate = core + 常数 alpha” 这种稳定 alpha 显示成 0。

- 问题：数据库抽样核验若缩小历史候选池或套用最新参数，重算值就无法与保存的相似度结果直接比较；解决方案选择：沿用被抽日期保存的参数和完整候选池，仅限制目标股票，在签名校验后直接返回内存结果，跳过持久化、待重算记录清除与任务进度更新；解释：目标规模较小但历史准备成本仍保留，以计算口径一致性优先；旧算法版本不强行比较，标为抽样未完成。

- 问题：评分和走势相似度结果共库时，独立计算或查询会反复打开同一结果文件，写入相似度还会改变评分库；解决方案选择：相似度四张结果及配置表独立存入 strategy_similarity.db，计算/页面在内存数据库只读挂载评分、行情和相似度库，以临时视图维持查询口径；解释：相似度写入不触碰评分文件，读完关闭挂载连接才开相似度写实例；按用户要求不迁移、不回退读取评分库内旧相似度表。

- 问题：相似榜按日保存，但清除原始库维护记录也会改变行情文件签名，导致刚算的结果立即过期；解决方案选择：提交相似榜后只清当日欠账，再仅同步行情水位与本次输入相同的快照，保留各自评分、触发和资料签名及其他日期欠账；解释：维护记账变化不等于计算输入变化，避免再次扫描历史评分，同时中断最多留下需要重新计算的快照，不会把行情变更前的旧快照认证为有效，也不会因单纯清账让同一行情版本下已完成的其他日期过期。

- 问题：历史评分欠账会硬阻断已完成当日排名的每日走势相似任务；解决方案选择：走势相似计算不再以历史排名待重算记录作为入口门禁，历史欠账继续在排名页展示并由手动重算消化；解释：每日流程可以只计算最新一天，代价是相似度历史样本可能继续使用尚未按修订后行情重算的旧规则触发结果。

- 问题：云端相似榜只同步单日完整结果，而本机总榜快照只含最近五日，无法按默认 90 日样本间隔重新计算数据签名；解决方案选择：展示已有相似榜元数据时，本机历史足够则继续核验签名，本机历史不足则信任已同步的完整结果快照并明确标为未复核水位；解释：相似榜结果、元数据、参数和匹配证据已随快照完整传输，缺少的是重算输入，不能因此拒绝展示；代价是精简历史设备上的后续输入修订无法自动判定该快照过期，需由新云端快照覆盖或在完整历史设备重算。
