# 组件取舍

后续 agents 修改本组件时请继续维护本文件。

- 本 crate 聚合策略编辑、选股、排名、相似度、统计和回测应用用例。
- 这是应用层最大的编译单元；先与 market、data、chart 隔离，避免一次重构同时打散高耦合策略内部类型。
- 允许依赖 shared 与后端 backtest；不得依赖 facade 或 market。后续只有出现稳定的单向边界时才继续拆小。
- data/download/scoring/backtest 均直接依赖能力所有者，禁止重新引入聚合导出层。
- 评分共享类型从 `lianghua-model` 导入，结果库操作从 `lianghua-data::data::scoring_store` 导入；不得借 scoring 建兼容路径。
- 只运行 `cargo test -p lianghua-app-strategy`，不要因此触发全 workspace 测试。
- 问题：根包研究二进制为了复用完整策略研究用例而反向依赖整个应用层 crate，扩大根包编译依赖并违反能力所有权约束；解决方案选择：`strategy_dimension_research` 命令行入口与用例共同放在 `lianghua-app-strategy` 包内，根包删除该依赖；解释：CLI 本身也是该应用用例的入口，归属用例所有者可以保持实现复用，同时让根包继续只依赖 data、scoring、backtest 等底层能力所有者。
- 全市场触发近邻精排用触发次数推导的严格时序上界做剪枝，并用 101 个分数桶代替全候选排序；这是为了在保持精确 Top-K 语义的同时，线性地优先填满堆并提高后续 DP 剪枝率。
- `strategy_trigger_similarity_summary` 只保留日期、股票和排名，供 `S_RANK` 按日序列读取；详细榜继续承载解释字段。配置或策略/指标定义改变时清空历史汇总，避免表达式混用不同口径，日常行情与评分重算则保留逐日快照。
- 问题：单股拟合内部上报候选扫描进度会让多个并行股票争抢进度状态，页面消息频繁跳动；解决方案选择：精排阶段仅在每只股票完成时上报一次累计股票数，不再上报单股开始或候选扫描位置，索引/权重仍使用独立阶段；解释：进度条只表达稳定、可比较的股票完成量，减少热循环中的锁竞争和轮询噪声；批次查询另外更新消息以定位具体 SQL 步骤。
- 问题：安卓长尾股票难以靠页面反馈还原耗时；解决方案选择：记录阶段切换、精排规模以及耗时至少 5 秒的股票，写日志前释放进度锁；解释：保留慢任务证据，同时避免逐股日志噪声及日志 I/O 阻塞进度查询。
- 问题：并行完成计数可能乱序写回，且累计耗时混入当前阶段会高估剩余时间；解决方案选择：持有进度锁时丢弃同阶段较小计数，单独记录阶段起始时间；解释：保持阶段内进度单调，并让预计剩余时间与当前阶段的工作量对应。
- 问题：全市场精排曾为每只目标构造最多 30 个含多组字符串和匹配规则名的完整明细，最终却只保留前 5 条；解决方案选择：统计阶段只传递轻量数值样本，仅为最终前 5 条构造展示数据，并让触发指纹中的规则名只在首次出现时复制；解释：保持排名和后验统计口径不变，减少全市场任务中的短命字符串分配与复制。
- 问题：临时规则回测曾同时保留全量 `ScoreDetails`、所有规则的嵌套触发 HashMap 和批内稠密评分列；解决方案选择：评分阶段直接返回引用总榜行和规则序号的紧凑触发行，股票筛选原地重映射下标，贡献度直接读取总榜排名，backtest 再按规则批次生成稠密列；解释：让 `parallel_batch_size=1` 真正限制规则计算峰值，并消除进入 backtest 前的字符串明细峰值。
- 问题：全策略回测把完整明细累积到返回数组后，Rust 结果、Tauri 序列化和前端 JSON 会在交付阶段叠加内存峰值；解决方案选择：每个策略线程算完摘要、样本、分层和相似度后立即将明细流式写入系统临时目录，主响应只返回摘要，点击时读取已算缓存且不重新计算；解释：继续由 `parallel_batch_size` 约束计算缓存，同时避免全量明细在应用层和跨端传输中常驻多份，新回测开始时清理上一轮缓存，失败的未提交缓存由写入器自动清理。
- 问题：逐策略构建相似度会为每条策略重扫一次区间内全部 `rule_details`，逐策略贡献度也会重复执行连接查询；解决方案选择：相似度只扫描一次并保存按 `(股票, 日期)` 的 64 位哈希排序紧凑行，查询时二分统计重叠；无限定股票池时贡献度改为一次 SQL 分组聚合，有限定股票池时保留逐策略过滤口径；解释：将主要数据库开销从随策略数增长的全表扫描降为单次扫描，同时避免恢复字符串键与逐键 `Vec` 的高内存缓存；64 位哈希存在理论碰撞但概率可忽略，换取显著更低的常驻内存。
- 问题：后验查询按锚点展开直到参考日的全部行情，同股多锚点会重复生成大量中间行，而每股单锚点使用新查询反而有额外开销；解决方案选择：同股多锚点时共用股票行情序号，通过 ASOF 定位后截取后续 N 行，每股单锚点保留原查询；解释：减少重复展开，不改变批次与并发，并保留停牌、锚点当天缺行情及先截取后过滤无效价格的语义。
- 问题：全市场相似精排为每个候选分别执行十余个量价和二十余个指标短向量点积，调用与分散内存开销在亿级候选对上被放大；解决方案选择：指纹构建时将通道分别归一化并压入连续数组，通道完整且非零时整组只执行一次长点积，缺失或零范数通道保留逐通道兼容路径；解释：减少短 AVX 调用和嵌套小数组，同时保持缺失通道重归一化及零向量的既有评分语义，仅允许浮点累加顺序带来的舍入级差异。
- 问题：90 日密集触发下几乎所有模板都命中共同规则，次数比例上界过松使大量候选进入时序 DP；解决方案选择：成功/失败模板按合入真实市场分的最终安全上界分别排桶，DP 前再用忽略一对一约束的双向最近日期匹配收紧时序上界，并在线程本地累计各层剪枝量后统一写日志；解释：放宽匹配所得分数必不低于真实有序一对一匹配，因而保持精确 Top-K，同时用线性时间上界换取对二次复杂度 DP 的提前淘汰证据。
- 问题：相关性研究 CLI 只能按触发频率取前 N 个并支持三种固定排序，无法覆盖全部 44 个规则，也无法做随机顺序稳健性检验，而样本外增量按前缀顺序计算且对顺序高度敏感；解决方案选择：为 `strategy_dimension_research` 增加可选的第 8 个位置参数（逗号分隔的显式规则列表，复用用例内的 `normalize_rule_names` 校验，仍受 20 个上限约束），由外部生成任意子集与顺序；解释：短历史规则（如仅 60 个有效日的“极端下跌”）一旦出现在前缀，共同日期交集会把后续所有规则的训练样本压到无法回归，因此覆盖和随机顺序研究必须显式控制规则列表并让短历史规则置尾或单独评估，不需要在用例里另造随机采样逻辑。
- 表达式回测只做有效性、稳定性、参数鲁棒性、重复性、增量性与样本检查，不再产出 `points`/`dist_points` 建议或最佳参数；`points`、`dist_points`、`total_score`、`rank` 仍只属于正式策略评分与排名体系，人工定分后继续交给 Ranking Compute 与 RankLayer 回测验证。禁止在表达式回测里重新引入自动定分、综合得分、评级或推荐字段。
- 表达式回测忽略正式策略的 `points`/`dist_points`：表达式内部按 ±1 计分、方向只取页面“方向”选择的符号，统计口径与正式分值大小无关（页面需明确说明这一点）；参数鲁棒性表默认不排序，禁止恢复“按 Spread 或其他指标预排序”，否则会被读成系统推荐某个参数。
- 问题：expanding walk-forward 的 fold 数量、首个训练窗口长度与增量回归最小训练样本必须固定，否则短区间会切出无法统计的样本外窗口；解决方案选择：fold 上限 8、首个训练窗口取 `max(长度/4, 20)` 个交易日、增量回归要求训练行至少 `max(30, 核心策略数 × 5)` 且样本外至少 20 个共同有效日，不足的 fold 标记 `status=insufficient`、只返回时间区间与样本数；解释：IC t 值与 ridge 回归都需要足够长的训练/测试序列，宁可少给一个 fold 的结论，也不要用几个交易日的噪声充当样本外证据。
- 问题：把 `insufficient` fold 从正窗口分母里剔除时，只在 1 个窗口里有效、其余窗口样本不足的参数会显示成 `1 / 1`，在鲁棒性表里看起来比 `3 / 4` 的参数更好；解决方案选择：正窗口分母固定为全部 fold，样本不足的窗口计入分母但不计为正窗口，并在单元格 tooltip 与段落文案里标注不足数量；解释：样本不足的窗口不构成“有效”证据，按非正处理是保守且可比的，只有只评估极少窗口这件事本身被显式暴露出来，用户才不会被分母缩小误导。
- 问题：holding period 的收益窗口会让 train 标签的实现日跨过 train/test 边界，而 `holding_period - 1` 的隔离天数恰好把“实现日等于 test 首日”的那一天留在训练集里；解决方案选择：每个 fold 在训练区间末尾与样本外起点之间固定排除 `holding_period` 个交易日（暴露为 `purge_days`），HAC lag 仍按 `holding_period - 1`；解释：purge 由持仓期直接推导，holding period = 1 时也至少排除 1 个交易日，从而保证任何 train 标签都不会用 test 首日行情；HAC 只修正重叠窗口的序列相关，不能替代边界隔离。
- 问题：核心策略彼此高度相关时，增量回归的正规方程会退化，普通最小二乘要么无解要么给出巨大且不稳定的系数；解决方案选择：先把 predictor 与 target 标准化，解 `(R + λI)β_z = r_xy`（λ = 0.1，复用 `dimension::{calc_linear_orthogonal_diagnostics}` 与相关性与正交研究同一口径），再换算回原始尺度，样本外增量按 `incremental = y_test - Σβ_i x_i_test` 计算（不减 train intercept），并把 predictor 数量限制为最多 8 个；解释：标准化后岭系数作用在单位方差上，共线方向上系数被平均分配而不是爆炸；test 不减 train intercept 时增量均值就是控制核心策略后的样本外增量 alpha，而减掉 intercept 会把训练期与样本外的水平差当成预测值吸收掉，让 “candidate = core + 常数 alpha” 这种稳定 alpha 显示成 0。
- 问题：每个 UNKNOWN 参数组合各自按自己的有效触发日切 walk-forward fold 时，参数鲁棒性表里各列的 fold 边界互不相同，正窗口数量不可比；解决方案选择：一次请求只从 eligible universe 交易日生成一套统一 calendar，所有参数组合共用同一套 train/test 日期与 purge，组合在某个 fold 内有效日不足 20 时只把该 fold 标记 `status=insufficient`（指标留空）；解释：只有日期一致时 “某参数在多少样本外窗口仍有效” 才能横向比较，触发稀疏的组合被如实标记为样本不足，而不是靠重新切日期获得更多窗口。
- 问题：负向规则（`points < 0`）的原始 IC 与 Top-Bottom Spread 已经通过分数符号/排序携带方向，工作时期望为正；早先统一乘 `direction_sign` 会把它们翻成负值，与顶部核心结果的原始 IC/Spread 口径不一致；解决方案选择：walk-forward fold 与日度序列里 IC、Spread 一律保留原始值，只对方向盲的 `avg_excess_residual_return`（残差均值）按表达式方向翻转；解释：秩相关与高低分半区差本身对分数取负是自洽的，`direction_sign` 只适用于“均值型”指标，页面列头因此标成 `IC`、`Spread（原始）`、`残差收益（方向）`。
- 问题：核心策略是增量回归的 predictors，结果库缺少其中一个时静默丢弃会改变回归含义而用户毫不知情；解决方案选择：请求里出现结果库中不存在（或区间内无有效触发）的核心策略时直接返回错误，列出缺失策略名并提示先跑 Ranking Compute；解释：predictors 集合就是研究口径本身，宁可让用户改选或补算评分，也不能用“少一个解释变量”的结果冒充增量研究结论。
- 问题：表达式组合与已有策略的相关性需要完整 eligible universe（未触发填 0），逐组合去结果库统计会在组合数量上重复全表扫描，用字符串键缓存全量触发明细又会放大常驻内存；解决方案选择：一次性读取结果库并按 universe 过滤成 `(pair_hash, universe_index, rule_index, score)` 紧凑数组（按 `pair_hash` 升序），每个组合用一次二分定位共同触发与叉积；解释：单次扫描 + 二分把每个组合的成本降到触发样本数的对数级，同时避免恢复字符串键映射；64 位哈希碰撞概率可忽略，与既有紧凑相似度缓存同口径。
- 问题：表达式回测的 Return Corr 与增量回归需要与相关性与正交研究可比的日收益序列，触发样本等权 `avg_excess_residual_return` 会被单日触发数量与分数幅度扭曲；解决方案选择：候选侧直接取 `RuleLayerPoint.score_weighted_residual_return`，已有策略侧在 eligible universe 内按同一公式 `Σ(score × residual) / Σ|score|` 逐日聚合（未触发分数按 0 计入分母的触发集合，单日触发数低于 `min_samples_per_day` 的交易日丢弃）；解释：分数加权口径同时携带方向与强度，负向策略工作时期望为正，跨策略可直接比较，也不需要再额外乘方向符号；Walk-forward 表仍保留方向调整后的日度超额残差均值，两类口径在页面文案中分别标注。
- `statistics` 拆为 `statistics/{mod,common,page,universe,market,detail_cache}` 与 `backtest/`、`validation/` 子目录；测试跟随被测文件（`#[cfg(test)] mod tests`），跨文件夹具放 `statistics/test_support.rs`，公共 API 仍从 `statistics/mod.rs` 汇总导出以保持 `strategy::statistics::*` 路径不变。
- `trigger_similarity` 拆为 `trigger_similarity/{mod,load,fingerprint,channel,sample,page,ranking/*}` 与 `test_support.rs`：测试跟随被测文件，公共 API 从 `trigger_similarity/mod.rs` 与 `ranking/mod.rs` 汇总导出，保持 `strategy::trigger_similarity::*` 与 `::ranking::*` 路径不变。
