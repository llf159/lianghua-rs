# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：全市场量比基准逐股请求历史日线和分时会拖慢平板监控，反复补齐也增加流量；解决方案选择：五日日均量统一批量读取本地 qfq 日线，分时由独立 4 线程池后台补齐并复用 HTTP 客户端；本地基准每 60 秒重读，失败或开盘窗口不完整时隔 60 秒重试，60 秒无轮询后丢弃排队任务，连接/请求超时沿用 6/12 秒；解释：4 并发平衡补齐速度、服务端负载和平板资源，60 秒容忍慢轮询并限制暂停后的后台抓取，也允许日线更新后重试。五日必须是行情日期前准确五个交易日，不能用库中任意最近五根替代；09:30–09:35 基准须覆盖完整窗口并保留已采集实时高点，补齐前禁用量比新高提示，以免不完整基准造成误报。

- 问题：本地日历可能过期，休市日的旧行情也可能落在固定交易时段内；解决方案选择：按北京时间连续交易时段检查，要求有效价格行情中严格过半数为当天、本交易时段且距现在不超过 180 秒，日历仅在行情无法确认交易时辅助解释；解释：多数样本避免单股时间异常，180 秒平衡供应商延迟、全市场分批抓取与停更识别，跨午休必须重新取得下午行情；正常盘中与非交易时段无需额外读盘或网络请求。

- 问题：模板预热缓存命中前重复编译，简单条件反复计算全历史，而直接缩短预热又会改变指标结果；解决方案选择：先按模板、股票/板块、相关文件修改时间与大小及北京时间日期查缓存；按股票完成全部模板后释放运行数据，无函数条件只求最新点，含函数模板保留完整求值并隔离赋值；解释：减少重复编译与临时内存，同时保留 EMA/SMA 原预热长度，避免以改变初值传播和结果换取速度。

- 问题：实时监控的五日涨幅与量比均量分别读日线，前者还对每股全历史排序且长期不刷新；解决方案选择：全市场监控共用一条聚合 SQL 和按仓库、行情日期缓存的日线基准，沿用量比的 60 秒刷新间隔；收盘价用 Top-N 保留最近六根，均量仍检查准确五个交易日；解释：一次扫描同时取得两类基准，减少重复读库与排序，代价是日线更新最多等待 60 秒；用 struct 包装空收盘价以保留日线位置，日历缺失只使量比基准不可用。详情页单股量比继续使用单股查询，避免为一只股票扫描全市场。
