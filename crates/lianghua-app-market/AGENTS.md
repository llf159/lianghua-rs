# 组件取舍

后续 agents 修改本组件时请继续维护本文件。

- 问题：逐股获取腾讯历史日线增加补齐延迟，北交所接口还可能只返回当天；解决方案选择：全市场统一批量读取本地 `stock_data` 的 `qfq` 日成交量，必须覆盖交易日历中行情日期之前的准确五个交易日，每股只请求腾讯分时；解释：本地复权只调整价格，成交量仍按手保存，腾讯分时及后续实时累计量按分时识别出的单位换算为手；不能拿库里任意最近五根旧日线替代目标五日。按来源目录和交易日隔离缓存，每 60 秒重读本地基准，让日线更新后失败项可自动重试。

- 问题：全市场全天量比基准需要逐股请求腾讯分时，同步补齐会阻塞平板监控，反复全量下载又增加流量；解决方案选择：用独立 4 线程池后台补齐并复用 HTTP 客户端，缓存当日曲线及监控期间最高值，后续用批量实时报价累计量更新，失败 60 秒后重试，60 秒无轮询后丢弃排队任务，恢复或跨日重新补齐；解释：4 并发平衡补齐速度、服务端负载和平板资源，超时沿用行情的 6 秒连接/12 秒请求配置，60 秒容忍慢轮询且避免暂停后持续全市场抓取，恢复后补齐遗漏走势；缓存修订号并入快照版本，让报价未变时后台完成仍能交付。补齐前只展示供应商当前量比，不触发全天量比新高；历史不足五日或没有 09:30 起点时保留缺失状态，不能把不完整历史当作全天基准。

- 本 crate 负责实时行情、盘中监控、龙虎榜和观察列表等市场用例。
- 允许依赖 shared 与 expression 应用 crate；不得依赖 strategy 或 facade，避免页面组合反向进入市场层。
- 后端能力直接依赖 data/download/scoring/provider 等所有者，禁止重新引入聚合门面。
- `RowData` 到表达式运行时的转换属于 data，市场用例不得经 scoring 间接导入。
- `scene_stage` 是市场域私有支持模块，不为跨域复用而扩大公开 API。
- 只运行 `cargo test -p lianghua-app-market`，不要因此触发全 workspace 测试。
- 问题：结果库文件可能正在重算、尚未建表或没有可用日期，自选水合若将排名查询视为必需会让已保存的自选记录无法打开；解决方案选择：行情、名称、概念、排名和场景均尽力读取，失败的来源只留空对应字段；解释：自选记录是独立持久化的用户数据，结果库只提供可选增强信息，不能反向决定列表是否可用。

- 问题：本地交易日历可能过期或误标，休市日返回的上一交易日行情也可能让固定时段判断误启动；解决方案选择：盘中监控按北京时间连续交易时段检查，要求有效价格行情中严格过半数为当天、本交易时段且距现在不超过 180 秒，日历作为辅助解释，仅在交易时段内行情未能确认交易时延迟读取，实时证据允许纠正本地日历；解释：正常盘中与非交易时段均无需为校验读盘或增加网络请求，多数样本避免单只股票时间异常，180 秒容忍供应商延迟与全市场分批抓取，又能识别行情停更，跨午休必须重新取得下午行情。非开盘仍交付一次快照后由页面暂停，即使数据版本未变也返回检查结果。排查命令 `cargo test -p lianghua-app-market market_activity_requires_session_and_fresh_quote_majority`。

- 问题：全市场每轮校验会重复解析大量相同报价时间，基础信息及排名缓存命中仍会整份复制，增加平板 CPU 与分配开销；解决方案选择：时间新鲜度仅在本轮按原始日期/时间组合复用，基础信息与排名缓存用 Arc 共享，指定股票筛选通过 Arc::make_mut 获取独立副本；解释：保留逐股多数判断和现有请求方式，每轮重新计算新鲜度以免跨轮缓存掩盖停更，筛选不能修改共享全市场缓存，缓存刷新与失效时机沿用原逻辑。
