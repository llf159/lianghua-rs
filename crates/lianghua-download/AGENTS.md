# 组件取舍

后续 agents 修改本组件时请继续维护本文件。

- 问题：删除原始库后保留的交易日历可能只从 2021 年开始，但末尾已到当年年末，下载 2010 年历史时会跳过日历刷新；解决方案选择：刷新判断同时检查日历首年是否晚于请求起始年和末尾是否覆盖当年；解释：首年检查避免非交易日导致起始日期无法精确匹配，末尾检查继续防止旧日历漏掉近期交易日。下次可运行 `cargo test -p lianghua-download trade_calendar_refreshes_when_requested_history_starts_earlier` 检查该场景。

- 问题：逐股整段补救的行情事务提交后，应用进程若在筹码修复前闪退，内存中的补救股票名单丢失，下次增量可能跳过这些股票的历史筹码修复；解决方案选择：仅补救写入时在同一个原始库事务内登记 `pending_chip_repair`，后续应用维护成功后清除；解释：行情与待修复标记同事务提交，崩溃不会出现已替换行情却没有标记的窗口。下次排查可查询 `SELECT * FROM pending_chip_repair`，确认尚待修复的股票。
