# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：下载分段提交或先删后补时，等到整轮结束才记录修复清单会留下源行情已变化、旧结果仍被当作可用的中断窗口；解决方案选择：前复权行情删除、单股写入、按日写入与相应清单共用事务，追加新日期记录后续待计算区间，覆盖或补写已有历史再记录筹码待修复股票并重置模型完成状态；解释：事务失败两者一同回滚，已提交阶段中断则保留记录供下次继续；筹码、评分和相似度覆盖记录按代码及日期判定，不逐字段比对，宁可对相同数据重复维护，也避免大规模数值对比成本。单股覆盖区间延至该股已有末日，按日覆盖包含旧数据中被删除、上游未再返回的代码，避免遗漏连续状态计算的影响。

- 问题：duckdb-rs 1.4.4 的独立 Connection::open 不共享数据库实例，同文件两个独立写实例先后 checkpoint 会覆盖彼此的目录和数据块；解决方案选择：概念维护入口消费并关闭下载源库连接后再重建，借用源连接的股票下载阶段不执行概念维护；解释：通过所有权交接保证清单清除的新写实例不会和旧下载实例重叠，避免只靠 CHECKPOINT 而仍留下旧实例缓存；首次、补全、增量入口都走同一交接过程。

- 问题：前复权价格按分取整后反算涨幅会随复权基准变化，自动补救先删历史又无法识别纯价格变化，导致概念/行业表现反复全量重建；解决方案选择：股票涨幅保留行情源返回的 pct_chg，价格和 change 仍沿用原取整口径；单股替换在同一事务比较旧表与暂存表落库精度下的日期及 pct_chg、amount、tor，仅为概念记录实际输入变更范围，按日覆盖只记当日；自动复权补救先持久登记计划，拉取成功才事务替换旧行情，显式历史清理仍保守记账；解释：概念权重来自成交额/换手率，与复权价格无关，也没有跨日递推。保留旧输入增加每只补救股票一次区间查询，但避免全市场历史重算；待补救计划继续阻断中断后的派生计算。旧版按复权价格取整反算的涨幅可能与源涨幅不同，首次重新下载仍需按实际差异补算；不自动清除已有待重算欠账，以免漏掉真实修正。数据源涨幅与按分取整的 close/pre_close 比值可能不同，这是刻意保留源涨幅精度。
