# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：跟踪表达式编译时若把赋值内联到引用处，`A1 := A0 + A0` 这类链式复用会让 AST 随赋值次数指数膨胀，26 行表达式即产生约 6700 万节点、编译耗时 69 秒，而 `ScoreConfig::validate` 在每次载入与保存时都会重新编译，足以卡死配置修改；解决方案选择：`TrackExpression` 保留赋值语句，按声明顺序逐条求值，只把不依赖当日跟踪上下文（AGE、冻结值及其派生的局部量）的赋值在整段历史上预计算为共享序列，其余语句每天用切片运行时重算；解释：以每天多执行几条语句换取编译的线性时间（160 行内联链 0 毫秒、486 个节点），代价是必须用 `derived_locals` 维护"哪些局部量随天变化"，因此不要为了减少运行时变量而恢复内联。
