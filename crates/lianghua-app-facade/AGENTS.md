# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：实时详情刷新重算全部自定义指标成本高，但指标之间可能通过内部赋值共享变量，递推指标又依赖历史初值；解决方案选择：按发布名称及赋值依赖筛选需重算的指标，仍按原顺序使用完整历史计算，不缓存数据库结果；解释：只筛直接引用名称会漏掉间接依赖，缩短 EMA/SMA 历史会改变结果，缓存计算数据则可能在下载或重算后展示旧值。

- 问题：坚果云会忽略 PUT 的 If-None-Match，首次建立索引不能靠它避免两台设备互相覆盖；解决方案选择：首次初始化使用 MKCOL 排他子目录，后续使用已验证的 If-Match 与十分钟租约；解释：MKCOL 对已有目录返回失败，能保护首次写入；若初始化在索引生成前崩溃，保守保留目录，须确认其他设备停止后手动删除 .bootstrap，避免按时间抢锁覆盖仍在初始化的设备。

- 问题：每个请求固定等待 3.2 秒会让无变化同步和目录读取也变慢，但坚果云免费版每 30 分钟限制 600 次请求；解决方案选择：进程内所有 DAV 连接共用最多 8 次突发额度、每 3.2 秒恢复一次额度的令牌预算；解释：短操作可以连续请求，持续批量操作任意 30 分钟最多约 571 次，保留余量；跨连接共享预算避免反复点击重置额度，其他设备及其他 WebDAV 客户端的请求仍依赖服务端限流与退避。

- 问题：原始 DuckDB 文件即便表内容相同，新建文件的生成元数据也会不同，直接按文件哈希会反复上传并产生假冲突；解决方案选择：总榜五个结果日期合在一个规范排序的 Parquet 数据库快照归档，相似榜最新一天另一个归档，下载后事务恢复到原数据库；解释：以实际表内容判断变化，避免依赖数据库内部二进制格式，也保证不删除本地其他日期。按用户要求，策略、自选、指标及图表配置、浏览习惯分别是四个固定版本包，整个包发生变化时重传；策略及配置历史持续保留，榜单旧快照只清理无冲突祖先，保留未解决分支。

- 问题：仅下载若复用同步租约，仍会写入云端索引，接收端就无法保持云端只读；解决方案选择：仅下载读取一次索引、按内容哈希取得并校验对象，复用本地备份及事务恢复，不取得租约、不合并分支、不执行云端清理；解释：保证所有云端请求只读，代价是其他设备在读取索引后清理对象可能导致下载失败，此时重新下载即可；该对象校验失败或缺失时不会应用本地替换。云端冲突仍跳过，本地在网络等待期间的变化仍保留。

- 问题：自选独立同步后若另建云端包或基线，旧设备与云端数据管理会出现两套自选版本；解决方案选择：按操作范围过滤上传、下载及旧路径，自选继续使用原 watchlists 包和同一租约/基线，管理页常规同步排除自选，版本管理仍允许显式恢复；解释：保留既有云端历史和冲突识别，自选操作不导出榜单数据库，也不清理榜单历史。

- 问题：原自选整包版本同步无法表达明确上传、下载或逐股合并，且现有记录没有修改时间和删除墓碑；解决方案选择：自选弹窗携带页面实际缓存条目（旧本地 JSON 可能滞后），下载/合并后同时返回条目以回写页面缓存；使用三个明确操作，上传以本地包取代全部云端当前分支，下载仅接收单一当前版本，合并取全部当前分支与本地名单并集、按股票代码去重，本地非空字段及已设置的开关优先；旧版本持续保留；解释：不靠整包时间推断逐股修改或删除，避免合并时误删另一端股票，代价是合并可能恢复单端删除的股票，传播删除需选择上传。明确替换/合并沿用手动恢复的独占门禁覆盖网络阶段，以本地操作期间等待换取不会覆盖同步期间的新编辑；普通同步仍按原规则释放网络阶段门禁。

- 问题：冲突分支内容是压缩包或数据库快照，管理页仅凭时间、大小和哈希无法判断哪个来自当前设备；解决方案选择：云端列表用当前仓库对应的本机同步基线标记“本机上次同步”分支，不为列目录重新导出和哈希本地快照；解释：基线能低成本、稳定地说明分支来源，但只代表上次同步状态，不声称等同于尚未同步的当前本地内容。

- 问题：策略资产的两端当前版本及同名备份可能内容不同，直接拼接规则会改变策略语义；解决方案选择：独立同步复用原 strategies 包及自选传输流程，合并按完整资产保留，本地当前版本优先，其他当前版本转为内容哈希命名的可见备份，同名冲突连同元数据另存；解释：以保留额外备份换取不静默丢失策略、不改变规则组合，哈希命名保证再次合并稳定；下载接收云端当前策略并自动备份本地，已有历史资产继续保留。

- 问题：L2主动、大小单和买方结构容易因字段缺失、有效零值或供应商口径不同被混成单一主力信号；解决方案选择：单股筹码页逐项计算并保留原始分母、当日及连续三个市场交易日均值，北交所标记为不可验证，不设研究阶段的1%／5%相容性硬门槛，也不向基础K/U注入任何L2质量；解释：成交证据与成本库存、模型身份必须分开解释，有效零值不能当缺失，停牌不能伪装成连续观测，未经产品验证的阈值不应暗中过滤页面证据。

- 问题：接收包后产生的自动备份及保留的历史会改变本地包，前端设置又可能未落盘，单个云端哈希无法同时代表共同祖先和已接收的本地状态；解决方案选择：分别记录云端版本、本地应用后哈希和设置待确认哈希，应用前持久化接收标记，接收失败的包暂停普通同步，须显式下载、恢复或选择策略来源；解释：无法区分中断的部分写入和中断后的新编辑，以额外本机状态换取失败可人工重试且不制造本地更新，自动保留资产随下一次实际编辑或显式上传传播，不为传播自动备份立即反向上传；旧基线没有额外状态时仍保守保留分支，不能猜测它们都来自自动备份。

- 问题：旧策略原文可能已无法被新版解析，但它仍是必须保留的历史资产；解决方案选择：同步历史 TOML 作为原文保存，语法校验只阻断四个直接启用的 TOML 配置，备份筹码原文件不生成业务页面；解释：避免无效历史阻断有效当前策略的接收，备份不因可传输就自动启用，显式激活仍走策略自身的解析校验。

- 问题：flate2 1.1.10 与 PNG 库分别要求不同版本的 miniz_oxide，而项目要求统一依赖版本；解决方案选择：将 flate2 固定在 1.1.9，使压缩与 PNG 共用 miniz_oxide 0.8；解释：保留原有压缩格式和接口，待上游依赖统一后再解除固定。
