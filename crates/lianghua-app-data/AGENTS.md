# 组件取舍

后续 agents 修改本组件时请继续维护本文件，只记录难以从代码理解的工程取舍；首次设计和普通 bug 修复不记，没有合适记录时不要硬写。

- 问题：全历史指标补算的一次性合并会使查询和事务内存峰值过高；解决方案选择：每累计约 131,072 行就合并提交并清空临时表；解释：以用户允许短时新增约 1GB 内存为预算，较大批次减少反复合并的开销，但行数不是硬内存上限；失败后已提交批次可由重跑覆盖。

- 问题：完整性检查在平板上扫描全库会争用计算资源，前收盘衔接检查还可能误报高价股票的价格舍入；解决方案选择：只读连接使用 2 个数据库线程、512MB 缓冲预算，衔接检查取最近 60 个交易日及前一日，误差容许 max(0.011 元，前收盘的万分之一)；解释：全库仍检查无效数值、覆盖与已有历史证据，近期窗口控制衔接排序成本，绝对与相对误差兼顾分位价格和高价股票的舍入。超过误差只能判为待核验，不能据此认证全部历史复权；512MB 不是进程总内存上限。
