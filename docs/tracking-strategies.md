# 跟踪策略

入口：**打分策略管理 → 选择场景 → 新建或编辑普通策略 → 开启后续跟踪**。跟踪设置与原策略一起保存。计算排名时同时产生跟踪分和事件状态，跟踪分在排名规则明细中查看；策略管理页不再提供独立的跟踪结果面板或回放入口。

## 满足或进步后计分

每个观察步骤可配置 `points`，首次完成该步时取得；跟踪本身的 `points` 是最终条件首次满足时取得的确认分。二者相加，之后每日保留同样的分数，不每天重复累加，也不因原发现条件、步骤条件、最终条件或当日资格回落而撤回。旧配置的所有分值默认为 0，继续只观察，不自动恢复原来的分值。

例如步骤分 2、确认分 3：起点当天跟踪分为 0，完成步骤后为 2，最终确认后为 5，后续仍为 5。原策略当天还有 6 分时，原策略与跟踪合计贡献 11 分；原策略当天是 0 分时，合计贡献 5 分。跟踪在规则明细与规则回测中以「跟踪·名称」独立列出，不混入原规则得分。跟踪分进入原规则所属场景和原评分阶段，不自动把场景阶段升级为 confirm。

```toml
[[track]]
id = "volume_rebound"
name = "缩量后反弹观察"
source = "原规则的稳定ID"
ttl = 20
capture = { A_LOW = "L", A_CLOSE = "C", A_VOL = "V" }
invalidate = "C < A_LOW"
eligible = "AGE >= 2"
steps = [{ name = "缩量", when = "V < A_VOL * 0.8", points = 2.0 }]
signal = "C > A_CLOSE"
points = 3.0
score_until = "SCORE_AGE >= 5"
```

这里的期限和分值仅用于演示配置语法。

- `invalidate` 成立即永久停止本事件并清零。“不失效”表示该条件没有触发。
- `score_until` 是**结束条件**，成立当天即清零、停止事件，之后条件回落也不恢复。它与失效条件都会优先于当天的进步或确认处理。
- `ttl` 限制等待进步和确认的观察时间。起点为第 0 日，第 1 到第 `ttl` 个市场交易日可以推进；每天最多完成一步，最终确认最早在全部步骤完成后的下一市场交易日。
- `score_until` 留空时，已经取得的分数保留到策略失效，不因观察期限结束而清零。期限外不再完成新步骤或取得新的确认分；尚未取得非零分的观察事件在第 `ttl + 1` 日到期，允许重新发现。
- `score_until = "AGE >= 10"`：在距起点第 10 个市场交易日结束。`score_until = "SCORE_AGE >= 5"`：在首次得分后的第 5 个市场交易日结束。`score_until = "SIGNAL_AGE >= 5 OR AGE >= 20"`：确认后最多保留 5 日，并在距起点第 20 日兜底结束。`score_until = "0"` 与留空相同：没有时间终点，已得分只在失效或数据不足时清零。
- 分值可以为负数，0 表示该步骤只观察。多条跟踪的已得分可以相加，来源分值始终使用未加跟踪分的原始结果，避免自我触发。
- 缺报价或当前阶段必要证据缺失时停止并清零；市场开市但股票停牌仍推进年龄，休市日不推进。

## 起点与表达式

管理界面自动关联当前普通策略并生成稳定 ID，单条改名不改变引用。关闭后续跟踪会停用并保留配置，删除原策略会级联删除跟踪。原规则或场景停用时，其跟踪不参与计算。

`source` 消费原规则实际分值，包含组合加分和原命中窗口，大于 0 时才建立起点，冻结为 `TRIGGER_SCORE`。同股同跟踪只有一个事件，重复发现不换起点、不延长期限；停止后至少等原观察期限结束，才允许新起点，保分中的事件继续占用位置。

基础表达式统一保留真、假、未知三态：缺值比较为未知，取反后仍为未知；未知 OR 真为真，未知 AND 假为假。只有最终为真才命中。基础评分在原 scope 窗口存在未知结果时不计分、不触发，组合策略也不猜测未知条件的命中数；跟踪直接复用该来源分值，不再另跑来源表达式或数值中间量校验。已有事件不再依赖原来源是否继续满足。算法更新后旧检查点须回放，已有历史评分需重算后采用新语义。

事件状态区分观察期内、期满保分中和已停止。期满保分期间不再推进步骤或产生新信号；停止事件在原观察期内仍占用原起点。

`capture` 只在起点取一次值，变量名以 `A_` 开头；局部赋值不在表达式之间导出。`eligible` 只限制当天能否完成新步骤或确认，不撤回已有得分。没有步骤时从起点次日起判断 `signal`，留空默认符合资格即成立；同时保存当日信号和首次信号日期。

可用上下文：

| 变量 | 含义 |
| --- | --- |
| `AGE` | 距起点的市场交易日数 |
| `TRIGGER_SCORE` | 起点的原规则实际分值 |
| `SCORE_AGE` | 首次取得非零步骤分或确认分后的交易日数，尚未得分时为 -1 |
| `SIGNAL_AGE` | 首次最终确认后的交易日数，尚未确认时为 -1 |
| `COMPLETED_STEPS` | 已完成步骤数 |
| `A_…` | 起点冻结值 |

上下文按当天推进前的状态求值。周期只从市场日历计算；行情算子的回看仍按个股实际行情序列。若只按 `SIGNAL_AGE` 设置终点而事件始终未确认，已取得的步骤分可能持续保留；需要兜底时用 `OR AGE >= …`。

表达式复用原算子。行情指标先按历史序列计算，事件部分按当天上下文求值。`LAST` 读取整段末值，在跟踪表达式和来源规则中禁止使用；原规则 `scope_way = "LAST"` 正常支持。`REF`、`CROSS` 不接受事件上下文；`EMA`、`SMA`、`BARSLAST`、`GET/GETD` 的输入不能含事件变量。周期依赖上下文时使用有固定上限的 D 函数。函数内部也保留未知：COUNT 的窗口不足或含未知时结果未知，EXIST 在已有确定命中时为真、否则证据不足为未知；IF 条件未知时结果未知，条件明确时只采用所选分支的结果。

`start` 可单独用于独立观察，也可与 `source` 同时填写：此时起点以 `start` 表达式为准，`source` 仍确定跟踪分的场景与评分阶段。这样可将原规则普通贡献设为 0，同时保留其发现条件和后续确认。编辑界面的“自定义起点”留空时仍要求原策略贡献大于 0。自定义起点与原规则表达式分别保存，修改发现条件时需同步更新。正式计分仍需要关联原规则；保存时会校验这一点。

## 排名算法与效率

统一评分 runner 的顺序是：

1. 每股一次读取本次规则和跟踪共同需要的行情字段，并批量注入依赖数据。
2. 原规则各算一次，先冻结跟踪所需的来源分值，再推进跟踪。行情指标预计算为可共享序列，冻结表达式仅在首次需要建立起点时准备，同股后续起点复用准备结果并重新取值；日常判断复用运行时，无剩余函数调用的表达式只算当天，仍含事件相关函数的表达式读取共享历史窗口。事件按市场日历与个股日期双指针向前扫描，每条跟踪只保留一个事件。
3. 已取得的分值保存在事件内，步骤或首次确认时才更新，读取当日跟踪分为 O(1)。跟踪与原策略分值各自生成规则明细，场景和总分再合计，最后执行原有排名排序。
4. 按股票保存配置签名、历史输入签名和最终事件检查点。连续增量且历史前缀一致时，只推进检查点之后的市场日；历史输入、来源分或日历改变时，该股从头回放；配置变化、回算旧日期或请求覆盖检查点时回放。
5. 事件检查点及对应日历经有界批次队列写入暂存表，与正式评分和排名在同一次最终事务发布。中断不会出现新排名配旧事件状态。沿用 32 股批次与 2 批队列限制在途结果。

事件推进的复杂度为 O(股票数 × 跟踪数 × 待推进市场日数 × 单次表达式成本)，不用为每个输出日重新搜索历史起点，也不另跑一次全市场跟踪任务。首次计算或失效股票需要回放全部历史。任意历史修订以及递归指标都可能影响当前事件，因此目前仍读取历史行情、重建历史指标并核对签名；续算节省的是事件推进，不能理解为整个排名任务只读取新增几天。

规则明细分别保存原规则分与每条跟踪分；多个跟踪不会重复补算来源表达式。使用统一 runner 的数据库、内存各评分模式及单股区间评分共享上述语义；直接调用基础表达式求值不会推进跟踪事件。旧结果中混入原规则的跟踪分需要重算，不能仅改显示名称后拿来作独立归因。

## 保存与回放

排名保存 `scoring_result.db` 中的 `strategy_tracking_state` 和 `strategy_tracking_meta`，每股保存最终事件及检查点，共享一份交易日历。后端保留的独立回放接口写入本机 `strategy_tracking.json`，不改写正式排名；策略管理页不再读取或展示该快照。

旧观察快照在算法版本变化后重新回放。运行期间检测到输入或配置变化时不提交混合结果。清理排名待重算记账后只同步维护水位，不重新推进事件。

盘中监控不会逐 tick 提交日线事件；目前尚未提供完整历史事件列表、子条件证据、独立跟踪收益评价及跨设备事件状态同步。
