# 卷积排名参数回测

项目将卷积参数回测保留为独立 Rust 命令：

```bash
cargo run --release --bin convolution_param_backtest -- \
  <数据目录> [回看交易日数] [Top-K] [持有交易日数] [训练集比例] [基准指数]
```

默认运行方式：

```bash
cargo run --release --bin convolution_param_backtest -- /path/to/stock_data
```

等价默认参数为：

```text
回看交易日数 = 500
Top-K         = 20
持有交易日数 = 5
训练集比例    = 0.7
基准指数      = 399300.SZ
```

如需覆盖结果库中的全部历史，可将回看交易日数设为大于结果库实际交易日数的值，例如：

```bash
cargo run --release --bin convolution_param_backtest -- \
  /path/to/stock_data 10000 20 5 0.7 399300.SZ
```

## 数据要求

数据目录至少需要：

- `scoring_result.db`：`score_summary` 提供每日股票总分。
- `stock_data.db`：`stock_data` 提供股票和基准指数的后续涨跌幅。

股票行情使用 `qfq`，默认指数使用 `399300.SZ` 的 `ind` 数据。

## 候选参数

回测会比较原始当日排名与以下卷积核：

- 窗口：2、3、5、10、15、20、30个交易日。
- 指数衰减：0.25、0.50、0.70、0.85、1.00。
- 双尺度核：10、20、30日长窗口，长核占比10%、20%、30%、50%。

生产默认核 `H30-L50` 始终包含在候选网格中：50% 三日快核 `[1.0, 0.7, 0.49]`，加50% 三十日等权均值。单元测试会校验它与后端生产核逐项一致。

## 回测口径

- 每日选卷积排名前 Top-K 只股票。
- 收益为后续持有期内股票 `pct_chg` 之和减去基准指数同期 `pct_chg` 之和。
- 时间序列按训练集比例顺序切分，不随机打乱。
- 训练集与验证集之间隔离一个持有期，减少前瞻重叠。
- 同时输出平均超额、相对原始榜增量，以及对重叠持有期修正后的 Newey-West HAC t 值。
- 候选选择只使用训练集；验证集仅用于样本外检查。

该工具用于复核和选择参数，不会修改任何数据库。

## 自动测试

```bash
cargo test --bin convolution_param_backtest
```

测试覆盖候选网格、核归一化、HAC t 值方向，以及生产 `H30-L50` 与回测候选权重的一致性。

## 真实数据实验结论（2026-08）

曾使用独立 Python 研究工具验证“让 CNN 自动学习卷积核”是否能替代固定的
`H30-L50`。研究工具完成使命后已从项目删除，只保留本节的实验口径、结论和
工程经验；当前生产实现和可重复验收均以 Rust 为准。

### 实验口径

- 数据范围：2024-02-22 至 2026-08-07，共 598 个交易日、5517 只股票、
  3,163,044 个完整样本。
- 特征：总分、排名百分位、分数变化、分数加速度；历史窗口为 30 个交易日。
- 目标：未来 5 个交易日相对 `399300.SZ` 的超额收益，单位为百分点。
- 评价：每日 Top20、Rank IC、换手率、最大回撤和 Newey-West HAC t 值。
- 验证：5 折 expanding walk-forward，训练/验证/测试之间保留 5 日隔离；
  神经网络使用 42、2024、2026 三个随机种子。
- 训练配置：50 epochs、batch size 1024。一次完整三种子实验约耗时
  1165 秒，约 19.4 分钟。

固定基线结果如下。收益是每日 Top20 的平均 5 日超额收益，不是年化收益：

| 模型 | Top20 超额（百分点） | 相对原始榜（百分点） | 相对原始榜 HAC t | Rank IC | 换手率 | 最大回撤（百分点） |
|------|------------|------------|------------------|---------|--------|----------|
| 原始当日分数 | 0.9016 | — | — | 0.0674 | 83.4% | -34.67 |
| H30-L50 | 0.9401 | +0.0385 | 0.25 | 0.0787 | 51.0% | -32.38 |

`H30-L50` 在该样本中提高了 IC，并显著降低了榜单换手，但相对原始榜的收益
增量 HAC t 仅为 0.25，不能解释成已经证明存在显著超额。保留它的理由是
平滑性、较低换手、实现简单和跨期可审计，而不是只看一次平均收益。

学习模型相对 `H30-L50` 的三种子结果如下：

| 模型 | 种子 | 日均增量（百分点） | HAC t | 正增量折数 | 换手率倍数 |
|------|------|----------|-------|------------|------------|
| 单卷积核 | 42 | -0.0181 | -0.15 | 1/5 | 1.46x |
| 单卷积核 | 2024 | +0.0810 | 0.82 | 4/5 | 1.34x |
| 单卷积核 | 2026 | +0.1085 | 1.06 | 4/5 | 1.34x |
| 多尺度 CNN | 42 | +0.0193 | 0.18 | 3/5 | 1.08x |
| 多尺度 CNN | 2024 | -0.1397 | -1.02 | 1/5 | 1.26x |
| 多尺度 CNN | 2026 | -0.0469 | -0.46 | 2/5 | 0.90x |

两个学习模型均未通过生产验收：收益方向跨种子不一致，增量 HAC t 未达到
1.96，部分结果依赖少数折，单核模型还明显增加换手；多尺度模型在种子 2024
下最大回撤恶化到约 -49.79 个百分点。因此不把学习权重接入生产，继续使用固定
`H30-L50`。

学习模型使用标准化后的四通道输入和非线性组合，它的权重不等价于一维
`total_score` 卷积核。即便某次回测更好，也不能把某一层权重直接复制到当前
Rust 排名器；必须先定义可部署的模型推理、归一化参数版本和特征兼容协议。

## 可复用的回测工程经验

### 数据与防泄漏

1. 特征窗口只能使用 `t` 到 `t-L+1`，收益标签只能从 `t+1` 开始。查询
   `start_date` 时仍要向前读取完整预热窗口，不能把锚点范围误当成数据范围。
2. 股票在窗口中缺少任意评分日时，应判定该窗口不完整，不能用股票自身的
   `shift` 跨过停牌或缺失日期，否则实际回看跨度会悄悄改变。
3. 横截面排名损失必须按完整交易日组批；随机拆散股票行会改变 Rank IC 的
   数学含义，也可能让同一天同时进入训练集和验证集。
4. 标准化统计量只能由训练段估计，再应用于验证段和测试段。时间序列必须
   walk-forward，训练与测试之间至少隔离一个持有期。
5. 多日持仓导致相邻标签重叠，普通独立样本 t 值会虚高。收益差异至少使用
   `holding_days - 1` 阶 Newey-West HAC 修正。

### 模型验收

1. 固定保留原始分数和简单平滑核作为基线。复杂模型只有在样本外稳定超过
   两个基线时才有部署价值，训练集胜出不算通过。
2. 不以单个随机种子、单个年份或单个最佳折做决策。至少检查多种子方向一致、
   大多数折为正，以及收益是否被某一折垄断。
3. 收益、IC、换手率和回撤必须同时验收。平均收益略高但换手率上升 30% 以上，
   通常会在交易成本后失去优势。
4. 模型“统计上更好”和“工程上可部署”是两个门槛。还需验证输入特征、归一化、
   推理算子、版本信息和 Rust/Python 数值一致性；不兼容的研究权重不得直接上线。
5. 验收门槛应在实验前固定，例如增量 HAC t ≥ 1.96、至少 4/5 折为正、
   三种子方向一致、换手率不超过基线 1.25 倍，避免看到结果后修改标准。

### 计算性能

1. 这类任务的主要操作是按日期分组、排序、Top-K 和滚动窗口，不是通用矩阵
   乘法。应先优化数据布局和算法复杂度，再考虑引入矩阵库。
2. 大样本训练应一次加载和编码日期/股票标识，复用特征数组与 walk-forward
   切分；横截面损失按整日批次向量化，避免逐股票 Python 循环。
3. Rust 分层回测只构建一次每日分组，并把每日任务交给 Rayon 并行执行。
   默认“按样本数分层”的同分数据库排名规则直接合并进首次排序，避免同一天
   再复制并排序一遍。
4. Top-K 指标最多需要 100 只股票。实现使用线性选择截出前 100，再只排序
   该小切片，使这部分从 `O(n log n)` 降为 `O(n + 100 log 100)`；比较器加入
   原始下标作为最终键，保证并列结果与稳定全量排序一致。
5. 默认 H30-L50 的 30 个 SQL `LAG` 可化简为 30 日滚动和加前三日修正项。
   一次本机真实库测试中，整段卷积计算约从 0.43 秒降到 0.26 秒；已落盘
   Top20 历史读取约从 0.123 秒降到 0.011 秒。这些数字只用于定位量级，
   不应替代目标机器上的固定数据基准。

## 后续变更准则

- 新卷积核先进入 Rust 回测候选，不能直接修改生产默认值。
- 回测报告必须记录数据截止日、收益单位、持有期、Top-K、基准指数、切分方式、
  隔离期和 HAC 阶数。
- 更换默认核需要同时满足统计验收、换手/回撤约束和部署兼容性，并保留旧核
  作为可复现基线。
- 性能优化必须用结果等价测试保护排序、并列、缺失窗口和 Top-K 边界语义；
  只有算法复杂度或真实基准明确改善时才保留。
