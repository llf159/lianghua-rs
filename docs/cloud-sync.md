# 坚果云 WebDAV 同步

除另有说明外，命令均在项目根目录执行。

在「设置 → WebDAV 云同步」填写地址 `https://dav.jianguoyun.com/dav/`、账号邮箱和[坚果云第三方应用密码](https://help.jianguoyun.com/?p=2064)。默认在网盘下建立 `lianghua-rs` 子文件夹，凭据保存在本机应用目录，不上传。

在「原数据 → 管理」点击「下载云端」仅接收云端当前版本，适合手机接收电脑的数据；替换前在本地备份，云端有冲突的分组跳过，网络等待期间发生的本机编辑保留。该操作不上传本机内容、不修改云端索引、不合并分支、不清理云端历史。点击「双向同步」则上传本机改动并接收云端版本。「云端数据管理」可按路径筛选、查看历史版本、恢复/启用版本和删除选定云端版本；「恢复/启用」会保存本机改动到云端并合并分支，属于会修改云端的操作。

策略资产中心的「同步云端」会读取真实文件内容，并提供当前本地、云端各分支和可用的上次同步云端基线对比。按文件查看增删行，可切换云端分支和显示相同文件；本机基线缓存缺失时明确显示无法判定修改来源，不按时间猜测哪端更新。「云端数据管理」的策略及配置版本也提供「查看内容差异」，数据库榜单快照仍显示版本信息。

两端均有策略改动时，分别选择合并后启用的打分策略与筹码策略来源，再点击「按所选来源合并并启用」。选择针对完整策略文件；同一个文件中的两套规则不会自动拼接。所有当前分支的历史资产取并集，未选中的当前策略转为备份，同名冲突连同备注另存。提交时重新核对本地内容和云端当前分支，预览后有编辑会停止并要求刷新差异。整包上传、下载继续保留，并增加明确的替换确认。

接收后的本地基线包含自动备份及保留的本地历史，与云端原包版本分开记录。因此仅云端更新、设备本地未再编辑时，不会因自动备份多出文件就反向上传或制造冲突；这些本地保留资产会在以后实际编辑或显式整包上传时一起上传。筹码策略替换前只备份旧文件原文，不要求旧策略能成功解析；历史策略原文即使语法已失效也仍能保存和传输，直接启用的四份 TOML 配置仍检查语法。应用报错或中断会留下接收标记，后续普通同步暂停该项，避免将部分写入或中断后的新编辑当成已同步内容；核对差异后，可明确选择下载、恢复或策略来源合并。浏览器设置等待下一次内容核对确认落盘，写入失败时重试接收，部分写入或期间又编辑时提示冲突，不直接将未完成的接收上传为新版本。已有旧版误报冲突不会自动消失，可在内容对比后选择来源合并。

Android 和 Windows 安装包内置 DuckDB parquet 扩展，读取或备份榜单快照无需临时联网安装扩展。Android 若旧版本报 `Extension Autoloading Error` / `Can't find the home directory`，请安装更新后的 APK；仅设置主目录不能补齐安装包缺失的扩展。重新打包命令：在 `ui/lianghua_web/src-tauri` 执行 `cargo tauri android build --ci --target aarch64 --apk`。

Tauri 构建使用 `src-tauri/rust-toolchain.toml` 固定 Rust 1.95.0，Android CI 使用同版本。此配置用于绕过本机 Rust 1.94.0 / LLVM 21 在 Android Release 代码生成阶段出现的 SIGBUS，目前未重新编译验证。缺工具链时执行 `rustup toolchain install 1.95.0 --profile minimal --target aarch64-linux-android`；在 `src-tauri` 执行 `rustup show active-toolchain` 和 `rustc -vV` 检查，应显示 Rust 1.95.0 / LLVM 22。上述安装和版本检查均不编译项目。

- 同步打分策略、筹码策略、全部策略备份及备注、计算时的策略快照、指标定义和图表指标文件；同步持久化的选股/验证/监控模板、自选名单及通用设置。
- 总榜只有一个数据库快照包，内部包含最近5个已有结果交易日的汇总、规则和场景明细；相似榜另一个数据库快照包，内部只包含最新1天的排名、汇总、元数据和参数。旧的无冲突数据库快照版本会清理，本地其他日期保留。
- 行情库、筹码库、回测明细、临时查询结果、设备目录和下载凭据不参与同步。
- 两端从同一版本分别修改时保留冲突分支，不自动覆盖；在云端管理中恢复选定版本可合并分支，策略及配置旧版本仍能恢复，榜单只保留当前快照及未解决的冲突分支。首次同步已有不同内容的设备同样保留两份。
- 自动替换或恢复前备份本地文件：打分/筹码策略进入各自现有备份列表；其他配置和被替换的数据库快照保存在数据目录的 `cloud_sync_backups`。
- 相同内容按 SHA-256 跳过；四个配置包使用 ZIP 存储成员后整体 gzip，榜单使用规范排序的 Zstandard Parquet 数据库快照包。下载先校验再应用，一个快照涉及的所有日期和关联表在同一个事务中恢复。
- 删除云端版本不删除本地；已经同步且未修改的本地副本不会自动重新上传。WebDAV 服务需支持强 ETag 和 If-Match 条件写入；首次索引用排他 MKCOL 子目录初始化，兼容坚果云忽略 If-None-Match 的行为。不满足安全条件时停止同步。普通同步意外退出的锁十分钟后过期；首次初始化若未生成索引便退出，需确认其他设备停止，再删除同步文件夹内的 `.bootstrap` 子文件夹重试。

最小验证命令：`CARGO_INCREMENTAL=0 LD_LIBRARY_PATH=/usr/local/lib cargo test -p lianghua-app-facade cloud_sync --lib -- --test-threads=1`。若 Rust 报增量编译 fingerprint 内部错误，可使用 `CARGO_INCREMENTAL=0 cargo check -p app --lib`，或 `cargo clean -p lianghua-app-strategy` 后重试。

「测算上传量」在本机按实际压缩与内容查重规则计算，不连接网盘；展示首次上传、每次榜单快照与每月 22/31 次更新的估算。没有相似榜结果时会提示缺项。月估算按每天上传一份新的完整数据库快照计算，反复重算的新版本与索引请求会增加流量；删除云端旧数据不会返还当月已用上传额度。同步完成后分别显示上传和下载字节，包含该次索引控制文件与重试请求正文。

命令行本机测算（不上传）：`LD_LIBRARY_PATH=/usr/local/lib cargo run -p lianghua-app-facade --bin cloud_sync_diagnostics -- estimate <source目录> <本机应用目录>`。真实服务小数据诊断使用 `test <WebDAV配置JSON文件>`，只允许 `lhtest-` 开头的独立临时目录，完成后清理测试内容（坚果云禁止 WebDAV 删除顶层目录时，空测试目录需在网页版删除）；配置文件请限制为仅当前用户可读写，避免密码出现在命令行参数。

四个固定分组：`bundles/strategies.zip`（打分/筹码策略与全部历史备份）、`bundles/watchlists.zip`（自选及相关开关）、`bundles/indicator_config.zip`（`ind.toml`、`chart_indicators.toml`及其本地备份）、`bundles/browser_settings.zip`（浏览器保存的其余白名单配置）。按整个包判断变化和保存版本；策略冲突可以先分别选择两份当前策略的来源，再生成保留全部历史资产的新包。只重传发生变化的包。有数据的分组才生成快照。启用新分组和数据库快照后云端索引升级为格式 3，所有同步设备需更新；旧版单文件和按日包保留兼容读取，旧版单文件和按日包在对应新分组/数据库快照存在后仅展示为历史，避免重复应用。

数据库快照是可重建数据库的单个归档文件，里面包含所选日期的完整表数据与日期清单；不复制原始 DuckDB 文件，避免其生成元数据导致相同内容被误判为变化。短操作允许最多 8 次连续请求，随后按每 3.2 秒一次恢复请求额度；预算在同一应用进程的所有连接间共享。
