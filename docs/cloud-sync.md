# 坚果云 WebDAV 同步

除另有说明外，命令均在项目根目录执行。

在「设置 → WebDAV 云同步」填写地址 `https://dav.jianguoyun.com/dav/`、账号邮箱和[坚果云第三方应用密码](https://help.jianguoyun.com/?p=2064)。默认在网盘下建立 `lianghua-rs` 子文件夹，凭据保存在本机应用目录，不上传。

在「原数据 → 管理」点击「下载云端」仅接收云端当前版本，适合手机接收电脑的数据；策略及配置替换前在本地备份，排名替换需明确确认且不备份，云端有冲突的分组跳过，网络等待期间发生的本机编辑保留。该操作不上传本机内容、不修改云端索引、不合并分支、不清理云端历史。点击「双向同步」则上传本机改动并接收云端版本。「云端数据管理」可按路径筛选、查看历史版本、恢复/启用版本和删除选定云端版本；「恢复/启用」会合并云端分支；仅策略及配置会额外保存本机改动到云端，排名不会额外备份本机内容，属于会修改云端的操作。

策略资产中心的「同步云端」会读取真实文件内容，并提供当前本地、云端各分支和可用的上次同步云端基线对比。按文件查看增删行，可切换云端分支和显示相同文件；本机基线缓存缺失时明确显示无法判定修改来源，不按时间猜测哪端更新。「云端数据管理」的策略及配置版本也提供「查看内容差异」，数据库榜单快照仍显示版本信息。

两端均有策略改动时，分别选择合并后启用的打分策略与筹码策略来源，再点击「按所选来源合并并启用」。选择针对完整策略文件；同一个文件中的两套规则不会自动拼接。所有当前分支的历史资产取并集，未选中的当前策略转为备份，同名冲突连同备注另存。提交时重新核对本地内容和云端当前分支，预览后有编辑会停止并要求刷新差异。整包上传、下载继续保留，并增加明确的替换确认。

接收后的本地基线包含自动备份及保留的本地历史，与云端原包版本分开记录。因此仅云端更新、设备本地未再编辑时，不会因自动备份多出文件就反向上传或制造冲突；这些本地保留资产会在以后实际编辑或显式整包上传时一起上传。筹码策略替换前只备份旧文件原文，不要求旧策略能成功解析；历史策略原文即使语法已失效也仍能保存和传输，直接启用的四份 TOML 配置仍检查语法。应用报错或中断会留下接收标记，后续普通同步暂停该项，避免将部分写入或中断后的新编辑当成已同步内容；核对差异后，可明确选择下载、恢复或策略来源合并。浏览器设置等待下一次内容核对确认落盘，写入失败时重试接收，部分写入或期间又编辑时提示冲突，不直接将未完成的接收上传为新版本。已有旧版误报冲突不会自动消失，可在内容对比后选择来源合并。

Android 和 Windows 安装包内置 DuckDB parquet 扩展，读取榜单快照无需临时联网安装扩展。Android 若旧版本报 `Extension Autoloading Error` / `Can't find the home directory`，请安装更新后的 APK；仅设置主目录不能补齐安装包缺失的扩展。重新打包使用固定 Rust 1.95.0 和 128 MiB 进程栈：在 `ui/lianghua_web/src-tauri` 执行 `ulimit -s 131072 && cargo tauri android build --ci --target aarch64 --apk`。

- 同步打分策略、筹码策略、全部策略备份及备注、指标定义和图表指标文件；同步持久化的选股/验证/监控模板、自选名单及通用设置。
- 总榜只有一个数据库快照包，内部包含最新结果所用策略对应的最近最多5个结果日期的汇总、规则、场景明细和策略快照；计算快照不再进入策略包。策略来源与评分结果在同一事务发布，计算失败不会更新来源；相似榜另一个数据库快照包，内部只包含最新1天的排名、汇总、元数据和参数。旧的无冲突数据库快照版本会清理；只有快照相同的总榜才按日期更新并保留其他日期。
- 行情库、筹码库、回测明细、临时查询结果、设备目录和下载凭据不参与同步。
- 总榜快照不同或来源未知时暂停该项，需用户选择来源；选择云端将删除本地全部总榜历史并用所选包替换，不备份。接收总榜或相似榜若会替换本地已有日期，也必须先查看覆盖范围并确认；其他同步项可以继续完成。两端从同一版本分别修改时保留冲突分支，不自动覆盖；在云端管理中恢复选定版本可合并分支，策略及配置旧版本仍能恢复，榜单只保留当前快照及未解决的冲突分支。首次同步已有不同内容的设备同样保留两份。
- 上次接收榜单中断时，即使云端只有一个版本或已被删除，仍会暂停自动上传并显示处理入口。云端有版本时可选择“重新接收此版本”；确认本机榜单可用时，可选择“使用本机榜单”重新上传并解除接收保护。本机榜单若不完整，应先重新计算或恢复云端版本，删除云端文件本身不会解除保护。
- 自动替换或恢复前备份本地文件：打分/筹码策略进入各自现有备份列表；其他配置保存在数据目录的 `cloud_sync_backups`。排名接收或替换不创建本机备份，也不额外上传被替换的本机排名。
- 相同内容按 SHA-256 跳过；四个配置包使用 ZIP 存储成员后整体 gzip，榜单使用规范排序的 Zstandard Parquet 数据库快照包。下载先校验再应用，一个快照涉及的所有日期和关联表在同一个事务中恢复。
- 删除云端版本不删除本地；已经同步且未修改的本地副本不会自动重新上传。WebDAV 服务需支持强 ETag 和 If-Match 条件写入；首次索引用排他 MKCOL 子目录初始化，兼容坚果云忽略 If-None-Match 的行为。不满足安全条件时停止同步。普通同步意外退出的锁十分钟后过期；首次初始化若未生成索引便退出，需确认其他设备停止，再删除同步文件夹内的 `.bootstrap` 子文件夹重试。

最小验证命令：`CARGO_INCREMENTAL=0 LD_LIBRARY_PATH=/usr/local/lib cargo test -p lianghua-app-facade cloud_sync --lib -- --test-threads=1`。若 Rust 报增量编译 fingerprint 内部错误，可使用 `CARGO_INCREMENTAL=0 cargo check -p app --lib`，或 `cargo clean -p lianghua-app-strategy` 后重试。

「测算上传量」在本机按实际压缩与内容查重规则计算，不连接网盘；展示首次上传、每次榜单快照与每月 22/31 次更新的估算。没有相似榜结果时会提示缺项。月估算按每天上传一份新的完整数据库快照计算，反复重算的新版本与索引请求会增加流量；删除云端旧数据不会返还当月已用上传额度。同步完成后列出实际上传、接收的数据路径，并分别显示上传和下载字节，包含该次索引控制文件与重试请求正文。

命令行本机测算（不上传）：`LD_LIBRARY_PATH=/usr/local/lib cargo run -p lianghua-app-facade --bin cloud_sync_diagnostics -- estimate <source目录> <本机应用目录>`。真实服务小数据诊断使用 `test <WebDAV配置JSON文件>`，只允许 `lhtest-` 开头的独立临时目录，完成后清理测试内容（坚果云禁止 WebDAV 删除顶层目录时，空测试目录需在网页版删除）；配置文件请限制为仅当前用户可读写，避免密码出现在命令行参数。

四个固定分组：`bundles/strategies.zip`（打分/筹码策略与全部历史备份）、`bundles/watchlists.zip`（自选及相关开关）、`bundles/indicator_config.zip`（`ind.toml`、`chart_indicators.toml`及其本地备份）、`bundles/browser_settings.zip`（浏览器保存的其余白名单配置）。按整个包判断变化和保存版本；策略冲突可以先分别选择两份当前策略的来源，再生成保留全部历史资产的新包。只重传发生变化的包。有数据的分组才生成快照。排名与策略来源绑定后，写入操作将云端索引升级为格式 5，所有同步设备需更新；旧版单文件和按日包保留兼容读取，旧版单文件和按日包在对应新分组/数据库快照存在后仅展示为历史，避免重复应用。

数据库快照是可重建数据库的单个归档文件，里面包含所选日期的完整表数据与日期清单；不复制原始 DuckDB 文件，避免其生成元数据导致相同内容被误判为变化。短操作允许最多 16 次连续请求，随后按每 3.2 秒一次恢复请求额度；预算在同一应用进程的所有连接间共享。

选择排名来源时，界面列出本地历史范围及数量、各包日期和更新方式。只有本地所有结果日期都能确认使用同一份云端策略快照时，才允许按日期更新并保留其他日期；快照不同或存在未知来源时，必须明确确认删除本地全部总榜历史及关联明细，仅保留云端包内的日期。不创建备份，也不额外上传被删除的本机排名。使用本机只发布最新结果所用策略对应的最近最多五个结果日（相似榜一天），不改动本地历史。旧云端包混有多份策略快照时禁止接收，可在来源设备更新后重新上传单一快照的包。所选总榜策略随排名接收，不切换当前编辑策略；相似榜按列出日期更新并采用包内当前参数。确认后复核覆盖切片及本地数据库/WAL修改水位，预览后有修改需刷新。该操作会将云端当前分支按所选版本统一，已有云端历史仍沿用祖先清理规则。

旧结果没有逐日策略来源时显示“来源未知”，不使用当前策略或旧快照目录补造关联；明确选择后仍可传输，重新计算对应日期后获得可靠来源。旧策略包中的计算快照成员仅作为旧云端原始版本保留，新版不应用或重新打入策略包；旧基线有可校验缓存时会排除这些成员比较变化，已有真实策略分支仍需人工合并。计算页的策略对比读取最新结果日绑定的策略，避免将失败计算或其他设备传来的排名与旧本机快照配对。
