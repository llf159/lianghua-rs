# UI 工具应用层架构

`lianghua-app::ui_tools` 是供 Tauri 适配层调用的应用边界。内部模块按照业务能力划分，
不再沿用历史命令名称形成的扁平结构。

```text
ui_tools
├── shared       中立的日期、证券代码和股票元数据能力
├── chart        图表指标及指标配置
├── data         托管数据源的下载、导入和查看流程
├── expression   提供给适配层的表达式能力描述
├── market       实时行情和盘中市场观察流程
├── strategy     策略编辑、排名、分析和验证流程
└── facade       组合多个业务能力的页面级用例
```

## 依赖方向

- `shared` 不得依赖其他 `ui_tools` 业务模块。
- 各业务模块可以依赖 `shared` 和下层后端 crate。
- 同一业务域内的模块可以通过该业务域的 `mod.rs` 或私有子模块共享内部能力。
- 跨业务能力的页面组合必须放在 `facade`；其他业务模块不得反向依赖 `facade`。
- Tauri 适配层应使用规范的嵌套模块路径。根模块中的扁平别名仅用于兼容现有调用方。
- 通用表达式、持久化、数据提供方、评分和回测逻辑不属于 `ui_tools`，应放入对应的后端 crate。

## 兼容路径

`ui_tools` 根模块继续导出历史扁平模块名，例如 `ui_tools::details` 和
`ui_tools::strategy_manage`。新代码应分别使用 `ui_tools::facade::details` 和
`ui_tools::strategy::manage`。只有在明确进行 API 破坏性升级时，才可以删除这些兼容别名。

## 文件增长规则

每个公开模块应代表一个应用用例，或一组紧密相关的应用用例。如果某个模块需要复用原本
属于其他页面的辅助能力，应将该能力下沉到 `shared`、业务域私有支持模块，或更底层的后端
crate。不得仅为了复用 DTO、解析函数或查询辅助函数而让页面模块彼此依赖。
